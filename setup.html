m.Mo’s MeatWEBSITE SETUP
ONCE-OFF SETUP

One website.
One shared order book.

The shop works with WhatsApp immediately. Connect the shared database to enable admin sign-in, online order saving and access from both your phone and laptop.

You do not sign in with GitHub or ChatGPT on this website. Your Mo’s Meat admin email and password are created in step 2.

1. Create the shared database

  1. Create a project at Supabase. Keep its database password private.
  2. Open SQL Editor → New query. Paste the supplied database/schema.sql file and run it once in the new project.
  3. This creates the products, private order book and access rules. It adds the original flavours with 50g = R30, 100g = R50 and 200g = R90.

2. Create your admin login

  1. In Supabase, open Authentication → Users → Add user → Create new user.
  2. Enter your email and a strong password. Enable Auto Confirm User.
  3. Open the supplied database/admin.sql. Replace REPLACE_WITH_YOUR_ADMIN_EMAIL with that email and run it in SQL Editor.
  4. In the Auth settings, disable new user sign-ups if the project is dedicated to this shop. Customers do not need accounts.

3. Connect the website

Find your project URL and publishable key in Supabase’s project connection / API settings. A legacy anon key also works. Edit site/config.js:

window.MOS_CONFIG = {
  supabaseUrl: 'https://YOUR-PROJECT.supabase.co',
  supabasePublishableKey: 'YOUR_PUBLISHABLE_KEY',
  businessName: 'Mo’s Meat',
  whatsapp: '27827702275'
};

The publishable key belongs in the website. Access to customer records is controlled by the database. Never use a secret or service_role key in this file.

4. Host on GitHub Pages

Choose one route. You do not need to build the website or install any packages.

  1. Create a GitHub repository named mos-meat-website.
  2. Easiest: upload only the contents of site/ to the repository root. Make sure index.html is at the root, alongside app.js, styles.css, config.js, setup.html and mark.svg.
  3. Go to Settings → Pages → Deploy from a branch. Choose main and / (root). Save.
  4. Open the website URL GitHub shows. Share that URL with customers. Open the same URL on your phone and laptop.

Alternatively, upload the supplied source repository (including its .github folder), then choose GitHub Actions as the Pages source. The included workflow publishes only site/.

5. Check it is connected

  1. Open the shop. The connection notice should disappear and products should load.
  2. Choose Admin and sign in with the email/password from step 2.
  3. Add a test order, check its total and mark it paid. Open the site on your second device to confirm it appears.
  4. Use Products & prices to add a product or set its 50g, 100g and 200g prices. Hide products or leave a size blank when unavailable.
  5. Use Backup → Export JSON regularly. If importing an old backup, check the review flags and payment status.

Try it before going live

Choose Try demo to use the Test Customer profile without a password. Place practice orders, then open Test order book to edit, mark paid, pack or delete them. They stay on this device and never enter live analytics or send real messages. Reset demo clears only the practice space.

Install it as an app

After hosting on HTTPS, choose Install app. On iPhone, open the site in Safari, tap Share → Add to Home Screen, then open the home-screen app. On Android or desktop, use the install prompt or browser app menu.

New-order notifications

The open admin dashboard displays new-order alerts. For phone notifications while the app is closed, follow the supplied NOTIFICATIONS.md: run database/notifications.sql, deploy the worker and connect its webhook/scheduler. Add only the public VAPID key to config.js. In the installed admin app, choose Enable order alerts and allow permission.

Order alerts → Send background test checks the notification pipeline without creating an order or changing analytics. Backend setup and device permission are required before it can deliver.

Your existing orders

The uploaded file named JSON contains conversation text. It cannot restore saved orders. To move your real saved data, open the original order book in the same browser/device you used and choose Export JSON. Sign in to the new admin page, then choose Backup → Import / merge JSON. Existing IDs are skipped.

The spreadsheets have inconsistent dates, totals and some unspecified flavours. They have not been silently converted into live customer orders. Keep the original ZIP private; it includes customer information and business records.

What customers see

Customers browse the public catalogue, choose quantities and enter a name, WhatsApp number and optional note. With the database connected, orders are saved before the WhatsApp follow-up. Without it, the website prepares a WhatsApp message and the customer must tap Send in WhatsApp. No payment is taken online.

Customer records are visible only to an authenticated administrator. An Admin button or hidden page does not itself grant access.
